# DNG のレンズ補正(SIGMA fp 系)

SIGMA fp L の DNG に記録されたレンズ補正値を読み、自前のレンズ補正(`LensCorrector`)で掛けるための調査メモ。
実装は `Sources/RAWCore/Lens/DNGLensCorrection.swift`、テストは `Tests/RAWCoreTests/RAWCoreTests.swift` の `DNGLensTests`。

## なぜ自前で掛けるか

CIRAWFilter は fp L の DNG のレンズ補正に対応している(`isLensCorrectionSupported` が true で、実際に出力も変わる)。
ただし次の 2 点で、ARW と同じ 3 項目の補正(周辺減光・歪曲・倍率色収差を個別にオン・オフ)にはできない。

- 補正のオン・オフが 1 つしかなく、歪曲と倍率色収差を分けられない
- **DNG の周辺減光の補正値(GainMap)を使わない**。デコーダの補正がオンでもオフでも、GainMap を消した写しと出力が
  画素単位で同じだった(macOS 27.0、2026-10-25。`testDecoderIgnoresGainMap`)

そこで、デコーダの補正は切り(`CoreImageRAWSource` は全機種で切っている)、DNG の補正値を読んで自前で掛ける。
GainMap は Core Image が使わないので、自前の周辺減光の補正と二重にはならない。OS が変わって使い始めたらテストが失敗する。

## 記録されている値

RAW の画像の IFD(IFD0 の SubIFDs のうち NewSubFileType = 0)に、DNG 標準のオプコードとして入っている。
オプコードの並びは、ファイルのバイト順によらず常にビッグエンディアン。

| タグ | 中身 | fp L での実際 |
|---|---|---|
| OpcodeList2 (51009) | `GainMap`(番号 9)。デモザイク前の画像に掛けるゲインの 2 次元の表 | 31×21 点 × 1 プレーン |
| OpcodeList3 (51022) | `WarpRectilinear`(番号 1)。デモザイク後の画像の放射状の変形 | 3 プレーン(R・G・B) |
| ActiveArea (50829) | 有効な範囲 | 9536×6344(縮小記録は 6256×4160) |
| DefaultCropOrigin / Size (50719 / 50720) | 出力の範囲(アクティブエリアの中) | 8 ピクセル内側の 9520×6328(6240×4144) |

### WarpRectilinear

プレーンごとに kr0〜kr3(放射方向)と kt0・kt1(接線方向)、最後に光学中心 (cx, cy)(画像の幅・高さに対する比率)。
出力の画素から、入力のどこの色を取るかを決める向きの式:

```
r = 光学中心からの距離 ÷ 光学中心から一番遠い隅までの距離
f(r) = kr0 + kr1·r² + kr2·r⁴ + kr3·r⁶
入力の位置 = 光学中心 + f(r) × (出力の位置 − 光学中心)   (+ 接線方向の項)
```

`LensCorrectionData` の「倍率」と同じ向きなので、そのまま使える。fp L の 4 枚では、光学中心はちょうど (0.5, 0.5)、
kt0・kt1 は 0 だった。今のカーネルは画像の中心について放射状なので、接線方向の項は使っていない(0 でない DNG では近似になる)。

kr0 が 1 より小さい写真がある(SDIM7600、28-70mm の 46mm で 0.979)。補正した結果の四隅に画像の無い所ができないよう、
カメラが全体を少し拡大する分を含めて記録しているものと見ている。自前の `autoScale` は、この場合は 1 のまま(拡大しない)。

### GainMap

範囲(Top・Left・Bottom・Right)、表の点の数(縦・横)、点の間隔と原点(範囲に対する比率)、ゲインの表(float)。
ゲインは画素の値に掛ける(1 より大きいほど明るくする)。

## 換算(`DNGLensCorrection.data(from:)`)

`LensCorrectionData` は、出力の画像の中心を原点、半対角を 1 とする半径の関数。DNG の値はアクティブエリアの座標なので、
DefaultCrop の中心と半対角を基準に換算する。半径 0〜1 を 33 点に分けて値を取り、点の間は直線で補間する。

- 歪曲: `distortion(r) = f_G(r × 出力の半対角 ÷ 光学中心から一番遠い隅までの距離)`
- 倍率色収差: `chromaticRed = f_R / f_G`、`chromaticBlue = f_B / f_G`(プレーンが 1 つなら 1)
- 周辺減光: 出力の中心から半径 r の円の上(アクティブエリアの中)で GainMap を 720 点平均し、その逆数を係数 k にする
  (自前の補正は明るさを k で割るため)。表は 2 次元だが、同じ半径の上でのゲインの差は 0.001 EV 以下で、
  ほぼ完全に放射状だった(`testSampleGainMapIsNearlyRadial`)。放射状に近似しても精度は落ちない
- 撮影時のカメラ設定(`cameraSettings`)は 3 項目ともオン。DNG の補正値は、本来そのまま掛けるもののため

## 確かめたこと(実サンプル、`RAW_SAMPLE_DIR=RAWsample`)

### 歪曲・倍率色収差を Core Image の補正と比べる(`testWarpMatchesCoreImage`)

「デコーダの補正オン」の画像を基準に、画素の差の平均を比べた(縮小して描いた画像、リニア)。

| 写真 | 補正なし | 自前の補正 | 比べるための外れ(歪曲を 2 倍) |
|---|---|---|---|
| SDIM7600(28-70mm の 46mm、6240×4144) | 0.02868 | 0.00101 | 0.02847 |
| SDIM7513(35mm F1.4、9520×6328) | 0.00530 | 0.00083 | 0.00473 |

自前の補正は Core Image とほぼ同じ画像になる。残る差(0.001 前後)は補間のしかたの違いで、
歪曲の小さいレンズ(SDIM7513 は隅で 1.2%)では割合が大きく見える。

### 周辺減光(`testSampleDNGVignetting`)

Core Image は使わないので比べる相手が無い。補正で隅が中心に比べて明るくなる量が、換算した係数から見込む量と合うことを確かめた
(SDIM7600: 1.0278 倍・見込み 1.0286、SDIM7513: 1.1086 倍・見込み 1.1104)。補正の強さが実際のレンズと合っているか
(SIGMA の意図どおりか)は、均一に照らした被写体の写真が無く、まだ確かめていない。
